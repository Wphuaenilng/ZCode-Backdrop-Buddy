# BackdropBuddy · 长期规则

> 本页只保存跨版本仍然有效的安全与工程红线。当前状态看 `STATUS.md`，安装和使用说明看 `../README.md`。

## 产品与用户数据

1. **本地优先。** 不上传用户图片、视频、主题和使用数据，不引入账号或云端同步；需要改变这一边界时必须另行明确授权。
2. **不修改宿主安装文件。** 换肤和启动动画只走受控的运行时注入与恢复，不修改宿主安装目录、配置或应用程序包。
3. **用户数据默认保留。** 卸载、升级和清理不得默认删除用户主题、宿主 profile 或导出文件；任何清除动作都必须明确授权，并先验证目标确实是 BackdropBuddy 数据目录。
4. **主题包不是代码包。** 不接受主题携带的可执行 HTML、JavaScript 或任意命令；导入必须校验格式、路径、大小、媒体类型和包内容。

## 宿主与恢复

5. **身份不明就拒绝注入。** 只允许连接受支持的回环调试端口，并核验进程归属、页面目标和宿主指纹；任一关键校验失败都不得“尽力注入”。
6. **恢复是核心能力。** 应用、暂停、继续、重置和恢复必须保持状态一致；恢复失败、结果未知或部分窗口失败时，不得报告完整成功，并应保留快照与诊断证据。
7. **宿主升级后重新验证。** 不得仅凭旧版本截图或历史 profile 宣称兼容；至少复核识别、应用、暂停、继续和恢复。

## 架构与协议

8. **保持四层职责。** Shell 不写主题业务，UI 不直接访问文件系统，Kernel 不直接弹窗，PowerShell 不保存业务状态；跨层修改不得绕过正式 owner。
9. **协议必须受控。** 继续执行方法白名单、参数 schema、请求去重和单帧上限；大媒体走受控文件与媒体通道，不通过 JSON 帧内嵌，不执行 UI 提交的任意命令。
10. **文件访问必须有限定。** 文件选择、导入、导出和预览继续经过既有权限与路径策略，不因调试或临时修复放开任意磁盘读写。

## 验证、构建与发布

11. **验证结论不得扩大。** 自动化测试、真实宿主验收、人工视觉验收和未覆盖环境分别记录；局部通过不等于所有宿主、窗口、DPI 或输入方式通过。
12. **数字必须来自实际执行。** 测试数、文件数、哈希和性能数据不得从旧文档复制后冒充本轮结果；未执行就写“未执行”或“待核验”。
13. **标准构建走正式入口。** 完整构建使用 `powershell -ExecutionPolicy Bypass -File build\build.ps1`，不得用跳过测试或绕过 CSP、冒烟和布局检查的结果冒充正式交付。
14. **版本与发布分离。** 版本号只以 `build/version.json` 为来源；源码提交、构建、生成安装包和对外发布是不同动作，构建成功不等于已经发布。
15. **文档与磁盘冲突时先核实事实。** 当前状态只写入 `STATUS.md`，历史过程进入归档；不得把旧计划、旧聊天或历史验收记录当成当前授权。

# BackdropBuddy 用户体验与流程优化执行计划

> 创建日期：2026-11-08
> 当前状态：**待执行**
> 基线版本：0.1.4
> 依据：当前源码与文档的静态流程审查；文中“现状”是代码事实，不代替本轮实机复现。
> 目标：不继续堆叠功能，优先完成“首次能接入、状态能看懂、失败能恢复、日常少操作”。

---

## 0. 执行方式

### 0.1 任务顺序

按 **UX-01 → UX-17** 的顺序实施；同阶段内可并行，但不得越过依赖关系。每个任务独立形成可验收改动，不把全部优化压成一次大重构。

| 阶段 | 任务 | 目标 | 完成后再进入下一阶段的条件 |
| --- | --- | --- | --- |
| A：主流程止血 | UX-01～03 | 修复宿主接入、试穿和 WE 长列表三个断点 | 三项 P0 验收全部通过 |
| B：状态可信 | UX-04～05 | 应用、切换、刷新、保存不再误报 | 故障注入与真实宿主对账通过 |
| C：降低操作成本 | UX-06～10 | 控制台、WE、预览、导入和草稿保护 | 核心流程与窄窗口验收通过 |
| D：高级能力易用化 | UX-11～15 | 调度、托盘、异常恢复、可访问性、新手引导 | 全量回归与键盘验收通过 |
| 可选增强 | UX-16～17 | 开机常驻、全局快捷键 | 单独评估，不阻塞上述交付 |

优先级定义：

- **P0**：阻断主流程，或使“已验证/已运行”失去可信度。
- **P1**：显著增加新手理解成本、日常操作成本或数据丢失风险。
- **P2**：效率与完整性增强，可在核心流程稳定后实施。

### 0.2 每项任务的完成定义

只有同时满足以下条件，才能把任务标为完成：

- [ ] 实施步骤全部落地，相关按钮、空状态和错误状态均有实现。
- [ ] 自动化测试覆盖新增逻辑；不能只依赖现有 JSDOM 挂载冒烟。
- [ ] 按任务验收步骤完成真实界面操作，记录窗口尺寸、宿主和结果。
- [ ] `npm run build --prefix ui`、UI 挂载冒烟、全量内核测试通过。
- [ ] 涉及宿主操作时，至少验证 ZCode；影响通用宿主或切换时，再验证 ChatGPT 与一个向导宿主。
- [ ] 应用、暂停、继续、重置、恢复原貌的既有行为无回归，宿主安装文件仍不被修改。
- [ ] 在本文末尾填写执行记录；未实测的项目明确标为“未验证”，不得写成已完成。

### 0.3 不变边界

1. 保持本地优先，不引入联网、账号、云端素材或遥测。
2. UI 不直接读写任意文件；文件访问继续经过 Shell 路径令牌与内核校验。
3. 不为改善预览而放宽 CSP、CDP 归属校验、媒体校验或主题包安全边界。
4. 不改变“预览选中”和“宿主实际运行”的本质区别；新增状态必须能以 `status.get` 对账。
5. 自动切换、开机启动和全局快捷键不得绕过现有主题事务及宿主操作锁。
6. 本计划不重做视觉风格，不新增宿主、启动动画预设或主题参数。

## 1. 目标使用流程

### 1.1 新手首次使用

```text
打开控制台
  → 内嵌引导检测宿主
  → 自动接入；失败时才进入高级手动向导
  → 选择主题并预览
  → 点击“应用主题”
  → 看到“已确认运行”
  → 知晓可关闭到托盘继续运行
```

要求：

- 不使用强制多页教程，不在首次启动时连续弹窗。
- 重启宿主前明确说明会关闭当前宿主窗口，提醒用户先保存工作。
- 手动五步向导是自动接入失败后的高级路径，不是默认门槛。

### 1.2 日常使用

```text
选择主题 → 预览 → 应用
正在运行 → 暂停 / 继续
需要无人值守 → 自动切换 + 托盘常驻
出现异常 → 就地看到原因 → 重试 / 打开日志 / 恢复原貌
```

## 2. 阶段 A：主流程止血

### UX-01 · 打通宿主保存后的使用闭环（P0）

**现状依据**

- 向导保存后只更新内部 `hosts`，并尝试调用可选 `onSaved`：`ui/src/components/HostWizard.jsx:327`。
- App 渲染向导时未传 `onSaved`，控制台使用的外层 `hostList` 不会因保存自动刷新：`ui/src/App.jsx:1272`。
- 完成页却引导用户回控制台切换：`ui/src/components/HostWizard.jsx:728`。

**实施步骤**

- [ ] 将“宿主列表刷新”和“切换宿主”提升为 App 级动作；向导只提交保存结果，不维护一份脱离全局状态的宿主列表。
- [ ] `host.profile.save` 成功后立即重新请求 `host.profile.list`，处理重复 ID、内置宿主让位和当前选中项。
- [ ] 完成页主按钮改为 **“返回控制台并使用此宿主”**：先刷新列表，再调用现有宿主切换动作，最后回到控制台。
- [ ] 次按钮保留“返回控制台”，不强制切换；自动接入和手动保存使用同一闭环。
- [ ] 列表刷新或切换失败时留在完成页并显示持久错误，不能显示“接入成功且可用”的假完成态。
- [ ] 接入页默认突出“自动查找宿主 / 一键接入”；手动五步折叠为“自动接入不可用？使用高级手动接入”。
- [ ] 涉及启动或重启宿主的确认文案改为当前宿主名，并明确“会关闭当前宿主窗口，请先保存工作”。

**验收**

- [ ] 不重启 BackdropBuddy，保存一个新宿主后，控制台立即出现该宿主。
- [ ] 点击主按钮后，顶部宿主条、底栏和后续 `theme.apply` 均指向新宿主。
- [ ] 保存成功但列表刷新失败、切换失败两种故障均有原因和重试，不丢失已保存 profile。
- [ ] 自动接入失败后可进入手动向导，手动保存后走同一返回与切换路径。

### UX-02 · 让试穿结果严格绑定当前 profile（P0）

**现状依据**

- 试穿结果只在新测试开始时清空，修改字段或返回上一步不会使旧结果失效：`ui/src/components/HostWizard.jsx:313`。
- 保存按钮只检查旧的 `test.ok`：`ui/src/components/HostWizard.jsx:711`。
- `profile` 依赖遗漏 `fgVar`：`ui/src/components/HostWizard.jsx:300`、`ui/src/components/HostWizard.jsx:311`。

**实施步骤**

- [ ] 用完整、规范化的 profile 计算稳定指纹；覆盖连接信息、选择器、变量、`fgVar`、暗色配置、媒体交付及所有会影响试穿的字段。
- [ ] 修正 `fgVar` 等依赖遗漏，禁止以界面局部状态拼装出与显示值不一致的 profile。
- [ ] 保存 `testedFingerprint`；只有 `test.ok && testedFingerprint === currentFingerprint` 时才允许保存。
- [ ] 任何相关字段变化、重新点选或返回修改，都使旧验证结果失效，并显示“配置已变化，请重新试穿”。
- [ ] 为试穿请求增加递增序号或等效取消机制；旧请求晚返回时不得覆盖新配置状态。
- [ ] 试穿期间禁止返回修改，或允许修改但明确取消当前测试；两种交互选一种并保持一致。

**验收**

- [ ] 试穿通过后修改根容器、面板、背景变量、文字变量或媒体交付，保存按钮立即不可用。
- [ ] 只修改 `fgVar` 后再次试穿，内核收到的是新值。
- [ ] 连续发起两次测试，第一次较晚返回也不能把第二次配置标为已验证。
- [ ] 未修改配置时，试穿通过仍可正常保存，不引入无限失效。

### UX-03 · 修复 WE 桌面长列表不可达（P0）

**现状依据**

- 桌面 `body` 与 `.main` 为 `overflow:hidden`：`ui/src/styles.css:28`、`ui/src/styles.css:129`。
- Workshop 普通结果容器没有桌面纵向滚动约束：`ui/src/styles.css:1076`、`ui/src/styles.css:1189`。

**实施步骤**

- [ ] 为 WE 视图建立明确的纵向布局链：`height:100%`、`min-height:0`、结果区 `overflow-y:auto`。
- [ ] 保留页面级顶栏和底栏固定，不通过放开整个 `body` 滚动破坏其他页面。
- [ ] 将批量选择摘要与“导入所选”放入结果区底部粘性操作条；无待操作项时不遮挡卡片。
- [ ] 保证聚焦卡片、错误提示和最后一行按钮不会被粘性条遮住。
- [ ] 暂时保留串行导入，不在本任务同时改并发或协议。

**验收**

- [ ] 分别用 1、50、300 条扫描结果，在 1440×900、1100×720、1024×600 下滚动到最后一张卡片。
- [ ] 最后一行卡片与批量按钮可见、可点击，横向无异常滚动。
- [ ] 键盘 Tab 到靠后项目时自动滚入视口。
- [ ] 控制台、设置和本地导入的既有滚动行为无回归。

## 3. 阶段 B：状态可信

### UX-04 · 分离应用中与已运行，并串行化宿主操作（P0/P1）

**现状依据**

- 应用请求前就把新主题设为运行中：`ui/src/App.jsx:526`。
- 失败后直接清空运行状态，没有重新读取实际主题状态：`ui/src/App.jsx:550`。
- 宿主切换与应用可以并发，既有文档也明确内核侧未形成完整互斥。

**实施步骤**

- [ ] 明确拆分 `selectedThemeId`、`applyingId` 和已确认的 `runningId`；选择预览不得改写运行态。
- [ ] 新增统一宿主操作状态，至少覆盖 `apply / host.use / pause / resume / reset / restore`。
- [ ] 同一时刻只允许一个宿主操作；冲突按钮显示进行中和禁用原因，不排队执行用户无意重复点击的旧操作。
- [ ] `performApply` 请求期间只显示“正在应用”，成功后依据响应和 `status.get` 设置运行态。
- [ ] 失败时保留上一次已确认状态，不直接设为 `null`；随后用 `status.get` 对账。
- [ ] `status.get` 遇 `BUSY` 时有界重试，建议 200/500/1000 ms 三次；仍失败则标为“状态待确认”，保留旧数据并提供手动刷新。
- [ ] 自动切换与手动操作共用同一互斥边界；如需内核锁，在内核统一返回可读 `BUSY`，UI 不做无限重试。

**验收**

- [ ] 延迟 `theme.apply` 时，旧主题仍标为运行，新主题只标为正在应用。
- [ ] 新主题应用失败而旧主题仍运行成功时，界面仍显示旧主题，不出现“未运行”误报。
- [ ] 应用中不能切换宿主或重复暂停；切换中也不能应用主题。
- [ ] 应用、暂停、继续、重置、恢复后，UI 与真实 CDP 注入状态一致。
- [ ] 对账失败不会清空旧数据，并能通过手动刷新恢复。

### UX-05 · 统一加载、刷新、保存与错误反馈（P1）

**现状依据**

- 主题库失败被转换为空数组：`ui/src/App.jsx:138`。
- 手动刷新不检查结果，始终提示刷新成功：`ui/src/App.jsx:1135`。
- 成功与失败共用 2.6 秒 Toast：`ui/src/App.jsx:114`、`ui/src/components/Toast.jsx:1`。

**实施步骤**

- [ ] 为主题库增加 `loading / ready / empty / error` 状态；筛选无结果单独作为视图状态，不与空库混用。
- [ ] `refreshThemes` 返回明确结果或抛错，不再把失败伪装为空数组。
- [ ] 刷新失败时保留旧列表并标注“可能不是最新”，提供重试；首次加载失败则显示错误空状态。
- [ ] 仅实际成功后提示“主题库已刷新”；底栏同步显示加载、失败或就绪状态。
- [ ] 所有保存动作等待真实持久化结果，包括内置主题参数和选中主题；失败时保留编辑草稿并显示“未保存”。
- [ ] 保存、导入、调度规则提交增加 pending，按钮禁用并显示进行中，防止连点产生重复请求。
- [ ] 成功继续使用短 Toast；失败在相关表单或卡片内持久展示，提供“重试”和可展开的“详情”。
- [ ] 原始 bridge 英文超时信息只放入详情；主文案转为用户可执行的中文说明。
- [ ] 错误 Toast 使用适当错误播报；普通成功不抢焦点。

**验收**

- [ ] 分别模拟首次加载失败、有旧数据时刷新失败、真空库、筛选无结果，四种界面文案和 CTA 不混淆。
- [ ] `settings.set` 失败时不出现“已保存”，重新进入页面不会把内存假状态当成已落盘状态。
- [ ] 快速连点保存或导入只产生一个有效操作。
- [ ] 错误在 2.6 秒后仍可查看，并能从原位置重试。

## 4. 阶段 C：降低操作成本

### UX-06 · 重构控制台信息层级，不重做视觉风格（P1）

**现状依据**

- 预览使用所选主题，下方“当前主题”却可能显示另一个运行主题：`ui/src/components/ConsoleView.jsx:211`。

**实施步骤**

- [ ] 将预览区域明确分成 **“正在运行”** 与 **“所选主题”** 两层，名称和状态不得交叉取值。
- [ ] “正在运行”只展示宿主已确认主题、运行/暂停状态和当前宿主；无运行主题时显示明确空状态。
- [ ] “所选主题”突出预览和唯一主按钮 **“应用主题”**。
- [ ] 暂停/继续、编辑参数作为次操作；导出、下载素材、重置、删除收进更多菜单。
- [ ] “恢复原貌”与普通编辑操作分组，说明其作用是移除当前宿主皮肤，不删除主题。
- [ ] 主题卡增加“正在运行”徽标；选中态、运行态和暂停态不能只靠同一种颜色表达。

**验收**

- [ ] A 正在运行时选择 B，界面同时清楚显示“正在运行 A”和“所选 B”。
- [ ] B 应用成功后运行徽标从 A 转到 B，预览和状态一致。
- [ ] 新用户无需阅读文档即可区分应用、暂停、重置和恢复原貌。

### UX-07 · 补齐 WE 批量筛选、进度、取消与失败重试（P1）

**依赖**：UX-03。

**现状依据**

- 批量待处理项排除所有已有结果的项目，失败项也无法重试：`ui/src/components/WorkshopImportView.jsx:80`。
- 当前逐条串行导入，单条请求可能等待较长时间，缺少整体进度与取消。

**实施步骤**

- [ ] 增加标题/ID 搜索、全部/图片/视频类型筛选、全部/可导入/不支持状态筛选。
- [ ] 提供当前筛选结果的“全选可导入项”和“清除选择”；不支持、已成功和重复项不进入待导入队列。
- [ ] 失败项保留卡片错误并可重新勾选；批量结束后不要清空失败项选择。
- [ ] 增加 **“仅重试失败项”**，单条异常也写入对应卡片，而不只显示页面顶部错误。
- [ ] 批量期间显示“第 n/N 个、当前名称、成功/重复/失败数量”。
- [ ] 增加取消按钮。现有协议不支持中断单条导入时，文案必须为 **“完成当前项后停止”**，不得假装立即取消正在执行的磁盘事务。
- [ ] 批量期间禁止重扫描和重复启动批次；结果状态在离开页面前按 UX-10 保留。
- [ ] 继续串行导入；并行化不属于本任务。

**验收**

- [ ] 搜索和筛选不会改变原扫描结果，清除筛选后选择状态按既定规则保留。
- [ ] 构造成功、重复、失败混合批次，计数准确，失败项可单独和批量重试。
- [ ] 取消后不再开始下一项，当前项最终结果仍正确落到卡片。
- [ ] 300 条结果下筛选、选择和滚动仍可操作。

### UX-08 · 让预览与参数能力一致（P1）

**现状依据**

- 部分已有参数未进入预览计算：`ui/src/components/HostPreview.jsx:23`。
- 宽度不超过 1100px 时唯一预览被直接隐藏：`ui/src/styles.css:1143`。
- 新导入草稿与全局默认焦点分别为 0 和 50：`ui/src/App.jsx:16`、`ui/src/data/params.js:3`。

**实施步骤**

- [ ] 建立“参数 → 管理器预览 → 宿主实际效果”核对表，逐项覆盖铺放方式、水平/垂直焦点、`hpos`、缩放、文字安全区、面板/气泡和强调色。
- [ ] 修复视频预览的 `object-fit`、位置与焦点映射，不能始终按 `cover` 展示而忽略参数。
- [ ] 管理器能模拟的参数实时更新；不能准确模拟的参数旁标注 **“应用到宿主后生效”**，不宣称完全 WYSIWYG。
- [ ] 1100px 以下把预览移到表单上方、独立页签或可展开抽屉，不再 `display:none`。
- [ ] 把默认参数收敛到单一来源；新导入、设置和“复位”共用同一默认值。
- [ ] 明确“复位”是恢复主题默认值；若需要撤销未保存修改，由 UX-10 的取消负责，不混用语义。

**验收**

- [ ] 图片与视频分别调整每个可预览参数，均有正确可见反馈。
- [ ] 标记为“宿主应用后生效”的参数有实际宿主验收记录。
- [ ] 1024×600 和 1100×720 下无需恢复默认窗口尺寸即可看到预览。
- [ ] 新导入主题复位后与全局默认焦点一致，不出现左上/居中漂移。

### UX-09 · 完善本地导入与已有主题替换素材（P1）

**实施步骤**

- [ ] 文件选择后展示真实文件名、类型、大小；能探测时展示分辨率与时长。
